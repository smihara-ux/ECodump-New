# 全画面・共通基盤の実装状況

更新日：2026-09-25。今回のmain反映は、未コミットだった全画面の実装・API・DB・配置設定・検証資料をまとめたものです。

## 最新仕様（過去の報告より優先）

**総合インフォメーションは運営管理専用です。** 施工・受入のボタンは両テーマで暗い無効表示となり、直接URLでも記事画面を表示しません。業務セッションのAPIは記事・添付・操作履歴の取得と更新を403で拒否します。既存のコンポーネント・DB機能は保持していますが、独立した運営管理画面と運営認証は未実装です。旧資料の「施工・受入から記事を閲覧できる」という記述や画像は変更前の記録です。

## API・DBと依存関係

- [共通API](../app/server/index.mjs)、[32件のマイグレーション](../app/server/migrations/)、[検証用セットアップ](../app/server/setup.mjs)を収録。
- 施工・受入・ドライバーは共通の予約ID・便IDを参照。合意、予約承認、配車、運行報告、受入実績確定は別状態です。
- 予定数量・ドライバー伝票数量・受入確定数量を分離し、tとm³を混算しません。
- 権限制御、二重操作の防止、古い版の拒否、結果不明時の照会を含みます。
- 認証なしのサンプル画面、共有PostgreSQL画面、旧SQLite検証パネルは異なる保存境界です。
- 詳細：[共通API契約](narita-validation/API_CONTRACT_V2.md)、[検証データの管理場所](narita-validation/COMMON_LOCATION.md)、[三役割設計](ECO_DUMP_3ROLE_DESIGN.md)。
