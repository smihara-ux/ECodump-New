# ECO DUMP 横断検証結果

確認日：2026-09-25。対象：施工側・受入側・ドライバー、現在の未コミット実装を含むローカル作業ツリー。本番公開・本番データ利用なし。

## 判定

**匿名データによる通常業務の操作試験は可能。例外を含む現場での試験運用は開始条件未達。**

共通PostgreSQLで直接予約・発生土マッチの双方から実績確定まで保存、再取得、再ログイン、別ユーザーへの反映を確認した。予約変更・取消・配車変更・遅延・受入不可・確定後数量訂正は旧SQLite実装にはあるが、共通PostgreSQLには未接続。旧実装の合格を共通システムの合格として扱わない。

## 今回修正した問題

|問題・原因|影響|修正・再確認|
|---|---|---|
|旧SQLiteが操作キーだけで既存成功を返した|同じキーの異なる内容を保存済みと誤認|メソッド・URL・版・本文のSHA256照合を追加。異内容409。過去の指紋なしキーも安易に成功再送扱いしない。結果照会は維持。旧API3件再合格|
|旧直接予約画面が保存後の再取得失敗を握りつぶした|再取得できていないのに成功表示|保存処理で取得失敗を伝播。503を注入する画面回帰試験を追加|
|旧SQLite画面の共通DB表記が曖昧|別データを共通保存と誤認|旧SQLite・別データを明示し共通PostgreSQL画面へのリンクを追加|
|条件入力欄のアクセシブル名が初期本文を含んだ|ラベルによる入力の識別が不安定|明示的aria-label追加。直接予約の画面操作で再確認|
|共通画面のログアウトが詳細・タブ状態を残した|再ログイン直後に以前の詳細が開き、日付選択ができない|選択・作成・確認ダイアログ・タブ・通知状態を初期化。3役割の再ログインを含む横断試験で再確認|

既存の認証・マイグレーション・共通APIを活用した。共有作業ツリーの他担当変更を一括上書き・コミットしていない。例外フローの新規移植は未実施であり、修正済みとは扱わない。

## 残課題・優先度

|優先度|内容|次工程の完了条件|
|---|---|---|
|P1：現場試験前|変更・取消・再配車・遅延・受入不可・数量訂正を共通DBへ統合|3画面、履歴、権限、競合、枠の解放／再確保、結果照会まで接続し同じシナリオを再合格|
|P1：現場試験前|実機と実通信での受入|iPhone／Android、iPad等で入力、復帰、通信断、再ログイン、権限失効、操作サイズを確認|
|P1：共有環境移行前|ローカル検証認証から運用認証への接続|利用者ごとの本人認証・担当範囲・退職／権限失効・セッション管理を運用環境で確認|
|P2：運用仕様|車両前後59分の重複制約・数量単位・1予約1便・受入枠の妥当性|運行時間・必要余裕・単位換算・複数便予約の仕様を現場と確定し試験|
|P2：必要機能の確定|GPS・プッシュ・外部サービス・ファイル保管|必要性を決定し、採用する機能は実接続・拒否時・失敗時を確認。現時点は未確認|
|P3：表示改善|暗色の日付アイコン、補助文字と拡大表示|PC／実機の両テーマで判読可能な状態を確認|

P1は実地試験を止める課題。P2は用途と運用範囲に応じて開始前に判定する。P0相当の問題を今回検出していないことは、全体の安全性保証ではない。
