# 総合インフォメーション整理・実装記録

## 既存機能の棚卸し

|既存要素|扱い|
|---|---|
|現場掲示板の匿名サンプル|現場別情報の表示参考として維持。総合インフォメーションの保存先には流用しない|
|ヘッダー通知ポップオーバー|記事一覧とは別機能として維持|
|ドライバーのお知らせ|便・伝票・配車変更など業務状態の通知。記事公開とは統合しない|
|サイドバー上部の総合インフォメーションボタン|新しい共通画面への正式な入口として接続|
|メール・Push|未接続。記事公開時も `not_sent` とし、送信済み表示をしない|

## 実装済みの区分

- 運営共通: 有効な担当範囲を持つ利用者へ公開するサービス全体の記事。
- 会社内: 同じ会社の有効所属に限定。
- 現場別: 施工現場または受入場所の担当スコープに限定。
- カテゴリ: お知らせ / 運用案内 / 安全・注意 / 保守情報。
- 掲載状態: 下書き / 公開 / 取下げ。公開期間外は閲覧者へ返さない。
- 確認区分: `requiresAck=false` は閲覧のみ、`true` は版ごとに確認記録を保持。
- 添付: PDF / PNG / JPEG、1件1MB、3件まで。閲覧権限を持つ利用者だけ取得可能。

## 権限

投稿・編集・公開・取下げは `direct.info_grants` の明示付与が必要。施工・受入・会社管理などの既存業務ロールから自動継承しない。対象範囲は platform / company / site ごとに付与する。一般の施工・受入検証アカウントには編集権限を付与していない。

API/DBは公開先を再検証し、会社外・担当外の記事、添付、下書き、履歴を返さない。更新は Idempotency-Key と版番号で二重操作・古い画面からの更新を拒否する。結果不明時は操作結果APIで照会し、自動再送しない。

## 未確定事項と推奨案

|未確定|推奨案|理由|
|---|---|---|
|編集権限を付与できる担当|運営共通は運営責任者、会社内は会社情報管理者、現場別は現場責任者が申請し運営承認|施工・受入業務権限との混同を防ぐ|
|取引先へ会社内記事を共有するか|会社内とは別の「取引関係者」公開範囲を将来追加|会社内公開を拡張すると情報漏えいしやすい|
|確認期限・未確認者への催促|記事確認期限を別項目として承認後に追加|公開終了日時と確認期限は意味が異なる|
|メール・Push配信|記事公開後に明示的な配信操作を行い、チャネル別の配送結果を記録|公開成功と外部配信成功を混同しない|
|既存現場掲示板の移行|所有者・公開範囲を確定後に移行ツールを作る|匿名サンプルを実記事として扱わない|

## 検証境界

ローカル隔離PostgreSQLと検証認証のみ。DGX、本番Auth、実メール、Push、実利用者通知は未確認・未変更。
