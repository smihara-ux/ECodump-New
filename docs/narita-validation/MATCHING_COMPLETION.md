# 発生土マッチ：画面確認向け実装

2026-09-25 / ローカル隔離PostgreSQL / 正式一連テスト前

## 既存を活用した範囲

共通の `src/matching/SharedMatching.jsx`、`matchingApi.js`、`server/matching-handler.mjs`、`direct.match_*` を利用。施工・受入は同じ案件ID、相談、提示版、合意スナップショット、予約を参照する。新たな会社・現場・車両・予約の独自データは作成していない。

四つの区分（探す／自社の案件／相談・条件調整／成立済み）、下書き・公開・編集・公開終了、地域/土質/数量/単位/期間検索、公開・相談共有・社内の情報/資料区分、権限・版・冪等キー・結果照会は既存APIを活用。

通常未ログイン表示は既存の保存しない画面案。ヘッダーのログイン後、同じ画面内で共通DBを利用する。自動的な特権ログインは行わない。

## 今回の追加・修正

- 条件提示の前版との差分、および成立済み案件の合意時点と現在の案件条件の差分を表示。合意スナップショットを上書きしない。
- 成立画面に合意IDを表示。予約承認・配車は別操作であることを明記。
- 追加migration `20260925_matching_booking_reference.sql`: 予約に `match_agreement_id` を追加し既存合意からbackfill。UNIQUE/FKと同期triggerを設定。共有bookings応答の管理者向け `matchAgreementId` に返す。既存の合意行ロック・consultation一意性・booking_idの再利用と合わせて二重作成を防ぐ。
- 施工側管理／受入側管理へ戻る操作を追加。マッチ入口は既存のロゴ右ボタンを維持し縦メニューに重複させない。
- 距離・適合度に加え経路料金も未接続と明記。確定値を表示しない。
- 詳細選択時に詳細位置へスクロール。再取得で選択案件を更新し、権限/検索範囲から外れた古い詳細を残さない。

## 成田モデル準備

準備スクリプト: `app/server/tests/prepare-narita-matching-preview.mjs`
共通資産ID: `app/server/setup.mjs` の `naritaIds`
作成案件ID一覧: `matching-preview-cases.json`

A工区・B工区の搬出案件、栃木・茨城の受入案件を各担当者の既存認証で作成・公開した。第2種建設発生土、10m³、2026-09-25〜2026-12-31の架空検証データ。実際の採石場・空港工事・契約を意味しない。再実行は既存案件と他担当の編集を保持する。

相談・合意・予約は自動作成していない。画面で各担当者が相談→条件提示→同一提示版への双方合意→施工側の搬入予定指定→予約申請へ進める。予約申請はrequestedで作成し、受入承認も配車も自動確定しない。
