# WINNERS建設 成田モデル検証結果

更新日: 2026-09-25

## 検証境界

- 実API・DB: ローカル隔離PostgreSQL。施工、受入、ドライバーを別認証セッションで確認。
- 画面: ローカル Chromium。施工PC 1440px、受入タブレット 820px、ドライバー 390px。
- 実機・外部連携: 未確認。GPS履歴共有、Push、カメラ実機、外部ナビは対象外。
- 本番: 未変更・未公開。実在の成田空港工事・採石場・契約条件を示さない。

## 機能分類

| 分類 | 内容 |
|---|---|
| そのまま利用 | 認証セッション、担当範囲RLS、直接予約、受入確定、配車、4段階運行報告、受入実績、添付・伝票、操作ID照会 |
| 修正 | 成田モデルの固定ID・匿名名称を既存seedへ追加。施工、栃木受入、茨城受入、3ドライバー、担当外ユーザーを分離 |
| 追加 | 再実行可能seed、3便シナリオ試験、3役割の画面キャプチャ、証跡JSON、共通管理場所文書 |
| 接続が必要 | 外部運送会社所有車両の配車権限、1予約複数便、予約変更・取消、代車・代走履歴、遅延・受入不可・未着の問題報告、GPS履歴共有 |

## 確認済み

1. A工区から栃木モデル採石場へ10m³の直接予約を申請。
2. 栃木受入担当が別セッションで予約を確定。
3. 検証車両01・青木太郎を割当し、青木の別セッションに同一運行IDを表示。
4. 到着、出発相当（運行中）、受入先到着、荷下ろし完了を順序・版検査付きで保存。
5. 受入側が9.5m³を確定し、施工・受入・ドライバーの再取得で同じ値を確認。
6. 同じ車両の同日3便、A/B工区、栃木/茨城を別運行IDで確認。
7. 栃木担当から茨城予約、佐藤から青木便、担当外ユーザーから対象便が見えないことを確認。
8. 古い版での再配車は409、応答消失後は操作ID照会で適用済みを確認。
9. ログアウト後の新規ログインでも便が維持されることを確認。

API回帰は20件成功、Sites回帰は4件成功、production build成功。

## 未完了と理由

- 現行DBは `direct.trips.booking_id UNIQUE` のため、3便は3つの直接予約として管理した。要求する「1予約に複数便」はスキーマ・一覧projection・操作APIを同時に変更する必要がある。
- 現行配車APIは車両・ドライバーを施工会社所属に限定する。モデル運送を実所有会社として扱うには、施工会社と運送会社の委託関係、車両・運転手の利用許可、RLS、履歴を追加する必要がある。現在の画面はこの制約を明示する。
- 予約変更・取消、代車・代走、問題報告・運行訂正はAPI未実装。保存成功の表示は行わない。
- 前日・前週コピーとマッチングからの引継ぎは既存の画面試作／別のmatching API検証に存在するが、今回の成田seedでの共通DB一連試験には未接続。
- 原本伝票の提出・差戻し・訂正は既存共通API回帰で確認済みだが、今回の成田3便に専用画像を追加する試験は未実施。
