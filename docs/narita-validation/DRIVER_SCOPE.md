# ドライバー担当の作業境界（2026-09-25）

ドライバー画面は既存 `ConnectedApp` と `src/driver` を利用する。独自の成田seedや予約/運行テーブルは作成しない。共通担当の会社・現場・車両・運転手・予約・便ID、権限、配車変更・問題報告・訂正仕様に接続する。

現状利用可能：本人運行、4段階報告、写真＋手入力、原子的提出、受入側差戻し、履歴、操作ID照会、IndexedDB下書き。
修正：成田共通アカウント/割当表示、配車版変更時の入力再確認、予定10m³と原票9.5m³の分離。
追加：端末GPS状態と最終取得時刻（共有APIとは分離）、問題・訂正の操作UI。
接続待ち：成田共通seed/ID manifest、配車変更・問題報告・訂正API契約。既存の保存操作名は勝手に別名へ変更しない。

API担当への接続条件：報告は既存trip.versionで競合検出。伝票も配車版（またはtrip.version）を検査できる必要がある。旧画面/旧担当の送信を拒否し、元操作IDの結果照会は維持する。訂正は元報告を消さず履歴追記。受入不可は自動実績確定しない。

現時点の画面追加：GPSはユーザー操作時だけ端末内で取得し、取得中/未取得/取得済み/古い/取得不可と最終時刻を表示。管理側への共有は未接続。伝票下書きは取得時のtrip.versionを保持し、版が変わった場合は最新の割当を再確認するまで送信を止める。送信payloadにexpectedTripVersionを添付するが、サーバーの正式な版検査は共通仕様との統合時に確認する。画面だけの検査をAPI保護済みとは扱わない。
