# 公開版を土台にした受入側整理・通常画面API接続

2026-09-25。ローカルのみ。本番公開・本番データ利用なし。

## 変更内容

- 承認済みの上部ロゴ＋3ボタン、配色、開閉方式を維持。受入業務／運行管理／実績・設定のグループに整理し「運行ダッシュボード」の入口を復元。
- 受入管理がホーム。「受入場所別」の初期表示を維持。
- 労務安全・調整会議、事業モード選択、縦メニューのマッチ重複は復活させていない。
- 受入側のダッシュボードでは配車編集ボタンを搬入予約・受付への入口に変更。地図・タイムラインの既存表示は維持し、位置・運行値がサンプルであることを表示。
- 取引先・基本設定から既存の会社・ユーザー・車両・協力会社・登録申請・元請会社・入退場管理へ到達可能。入退場管理を車両受付に置き換えていない。
- 旧SQLite検証パネルを通常画面から除外。API・DB・マイグレーションは削除していない。
- 未ログイン時は操作プレビューを直接表示。保存を利用する際にだけ共通のログインダイアログを開く。ログイン後も同じサイドバー・ヘッダー内で表示。
- 通常画面のマッチに既存の共通APIを接続。下書き／公開／編集／相談／条件提示／双方合意／予約引継ぎ／添付資料と公開範囲／結果照会を既存処理で実行。
- 通常画面の施工側予約・配車・実績、受入側の場所別ホーム・予約確認・実績確定を同じDBに接続。二重の管理画面ヘッダーや専用検証画面へ移動させない。
- マッチの「現場から探す」「受入れから探す」を維持。同じ側の区分では自社公開案件であることを明示。相手側はAPIの権限内の公開案件を検索。距離・適合度の仮値を実データの計算値として表示しない。

## 操作方法

[受入管理](http://127.0.0.1:5199/?preview=app&role=receiving&page=transport)を開く。未ログインでもサンプルで画面操作できる。

実保存は「ログインして保存を利用」からローカル用アカウントで認証する。現在のプレビュー認証と本番認証は別。ログイン時にAPIから担当役割を確認し、異なる役割なら利用を拒否する。認証情報はこの資料には含めていない。

受入側の実データは、施工側の申請→受入側の予約確定→施工側の配車→ドライバー報告→受入側の実績確定の順。マッチ合意は予約確定・配車完了ではない。

ログアウト時はサーバーセッションを失効させる。保存結果が不明な操作は照会後にログアウトする。未ログインのサンプル編集はDBへ保存・送信されない。

- `regression.txt`：既存画面回帰。試作画面のテストも含む。共通DB保存件数とは区別する。

## 未接続・制約

- 受入場所・会社／ユーザー／車両等の台帳編集、旧入退場管理は既存試作のまま。実保存とは表示を分けている。
- 地図のGPS追跡、交通情報、規制・進入路判定は実接続未確認。保存済み便の実運行地図としては扱わない。
- 共通PostgreSQLの予約変更・取消・再配車・遅延・受入不可・確定後数量訂正は、この変更では新規実装していない。
- 総合インフォメーションは未実装案内を維持。
- 本番Auth・外部サービス・Push・実端末は未確認。本番公開なし。

旧画面とAPIを一括置換せず、既存の共通処理を通常シェルへ埋め込む構成にした。他担当の未コミット変更・マイグレーション登録を維持。試験を再実行する場合は未使用QA_DATEを指定し、匿名データと証跡が追加される点に注意する。
