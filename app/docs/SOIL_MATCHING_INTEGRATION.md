# 発生土マッチ・共通API実装

## 完成範囲

施工側と受入側が同じAPI・DBを使用し、案件の下書き、公開、編集、公開終了、条件検索、詳細確認、事前相談、条件提示履歴、双方同意、合意スナップショット、予約申請作成まで操作できる。

画面は「探す」「自社の案件」「相談・条件調整」「成立済み」の4区分。従来のサンプル比較画面は下段に残し、API接続済み領域と明確に分離した。

## 案件

- 施工側：搬出場所、地域、土質、数量、単位、搬出期間、公開情報、相談共有条件、社内メモ、関連資料メタデータ
- 受入側：受入場所、地域、受入可能土質、数量、単位、受入期間、公開情報、受入条件、社内メモ、関連資料メタデータ
- 状態：`draft`、`published`、`closed`
- 編集はversionを増加させ、古いversionの更新を拒否する。

## 情報公開

- 公開検索：`public_data`だけを返す。
- 相談当事者：公開情報に加えて`shared_data`を返す。
- 自社：`internal_data`を含む全項目を返す。
- 合意スナップショット：公開・相談共有項目と案件versionを不変保存し、後日の案件編集から切り離す。
- 生テーブルはブラウザへ直接公開せず、API/RPCで投影する。

## 条件合意と予約

条件提示は連番で履歴化する。新しい提示が行われると、それ以前の承認は無効になる。最新提示に施工側・受入側の双方が同意した時点で合意を作成する。

合意後も予約や配車は確定しない。施工側が「搬出予定・搬入予約を作成」を実行すると、合意条件から`requested`状態の予約申請を作成する。受入側による予約確定と施工側による配車は、後続の別操作である。

## 検索根拠

地域、土質、必要数量、対象期間の入力値との一致だけで検索する。距離・適合度は経路計算・採点ロジックが未接続のため、API接続領域では表示しない。従来サンプルに表示される数値は例示であることを明記する。

## テスト

- `npm run test:matching`：公開範囲、相談共有、社内情報遮断、双方同意、合意スナップショット、案件編集後の不変性、予約申請、権限外拒否。
- `npm run test:matching-ui`：2役割の案件作成・公開から相談、双方同意、予約申請、再読込までのブラウザE2E。
