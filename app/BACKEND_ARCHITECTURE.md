# ECO DUMP 本番バックエンド定義

更新日: 2026-08-26

## 1. 目的

ECO DUMPを画面デモではなく、建設発生土の搬出・受入マッチング、配車、位置把握、搬入実績、書類、協力会社権限を一つのデータモデルで扱う運行基盤にする。

## 2. 調査から確定した業務要件

UCR型マッチングは単純な会社紹介ではない。搬出工事と受入地の間で次を照合し、候補提示後も協議・書類審査・日別搬入枠の調整が必要になる。

- 工期と搬出・受入可能期間
- 総土量、日量、車両台数
- 土質区分、最大粒径、含水・有害物質試験
- 受入地固有条件、対象地域、搬入可能時間
- 運搬距離・所要時間・概算運搬費
- 日別受入容量と混雑度
- 必要書類、審査状態、調整履歴
- 搬出元・搬入先・車両単位のトレーサビリティ

根拠:

- [建設資源広域利用センター](https://www.ucr.co.jp/)は発生側と受入側の協議・調整および受入管理を担う。
- [国土交通省の検討資料](https://www.mlit.go.jp/policy/shingikai/content/001885668.pdf)では、工期・土質条件変更への調整、自治体を越えた調整、受入集中を避ける最適化がUCRの役割として整理されている。
- [UCR受入地一覧](https://www.ucr.co.jp/out/downloads/2026/ukeirechiichiran/ukeirechiichiran-2.pdf)には、受入時期、土量、単価、土質、試験項目、最大粒径、日別台数などの条件がある。
- [コブリス・プラス](https://fkplus.jacic.or.jp/)は工事情報の共有、相手工事の絞り込み、地図検索による官民マッチングを提供する。

## 3. 採用構成

### データ・認証

- Supabase Auth: 会社・支店・現場・役割単位のログイン
- PostgreSQL + PostGIS: 現場、受入地、車両位置、距離検索、受入圏判定
- Row Level Security: 自社、元請、協力会社、運行管制、受入地管理者ごとの行権限
- Supabase Realtime: 運行状態、到着見込み、受入枠、車両位置の更新通知
- Supabase Storage: 土質試験、許可証、契約書、搬入申請書
- Edge Functions: マッチング採点、ルート・料金計算、通知、帳票生成

公開クライアントにはpublishable keyだけを置き、service roleは置かない。公開スキーマの全テーブルにRLSを設定する。ビューは`security_invoker = true`を基本にする。

### 地図・経路

- MapLibre GL JS: PC・スマホのインタラクティブ地図
- 商用利用可能な正式タイルプロバイダー: 本番契約時に選定
- 経路API: 大型車条件、通行規制、高さ・重量制限に対応する商用ルーティングを選定
- 車両位置: 運転手アプリまたは車載GPSから15〜30秒間隔で送信
- ジオフェンス: 搬出現場・受入地への入退場を自動検出し、実績と照合

## 4. 中核テーブル

- `organizations`, `branches`, `profiles`, `memberships`, `roles`
- `projects`, `sites`, `site_members`, `contractor_relations`
- `soil_offers`（搬出案件）, `soil_demands`（受入案件）
- `soil_tests`, `acceptance_conditions`, `documents`
- `matching_runs`, `match_candidates`, `match_negotiations`
- `receiving_slots`, `transport_orders`, `dispatch_assignments`
- `vehicles`, `drivers`, `vehicle_positions`, `geofences`
- `gate_events`, `weighbridge_records`, `transport_tickets`
- `notifications`, `audit_logs`

全業務レコードに`organization_id`、必要に応じて`project_id`と`site_id`を保持する。重要な状態遷移は更新で上書きせず、履歴テーブルまたはイベントとして残す。

## 5. マッチング採点

必須条件を満たさない候補は除外する。

1. 搬出・受入期間が重なる
2. 土質区分、最大粒径、試験結果が受入条件を満たす
3. 必要総量・日量を受入可能量が満たす
4. 対象地域、車両条件、搬入時間帯を満たす

候補は100点満点で順位付けする。

- 距離・所要時間: 30点
- 期間一致: 20点
- 土量・日別容量: 20点
- 土質適合度: 20点
- 書類準備・事業者信頼度: 10点

自動確定はしない。「候補」「事前相談」「条件調整」「書類審査」「成立」「不成立」のワークフローを持ち、最終確定は権限者が行う。

## 6. 実装段階

### Phase 1: 現在の共有プロトタイプ

- 実データに近い匿名データ
- 全画面の操作、検索、登録、詳細、状態遷移
- UCR型マッチング候補と調整フロー

### Phase 2: データ基盤

- Supabaseプロジェクト、認証、RLS、PostGIS、Storage
- 現場・会社・車両・搬出・受入・候補の永続化
- 監査ログとバックアップ方針

### Phase 3: 地図・運行

- 正式地図タイル、経路API、GPS送信、ジオフェンス
- ETA、渋滞、日別受入枠、到着順のリアルタイム更新
- オフライン時の送信キューと再同期

### Phase 4: 審査・帳票・外部連携

- 土質試験・搬入申請・管理券・計量票
- UCR/JACIC等との連携可否調査と正式な接続仕様
- CSV/API連携、電子署名、通知、請求

## 7. 本番化前の決定事項

- UCRという名称・データ・ロゴ・外部システム連携の利用許諾
- 地図タイルと大型車経路APIの商用契約
- GPS取得への同意、保存期間、個人情報保護方針
- 発注者・元請・協力会社・運送会社・受入地の責任分界
- 土質適合をシステムが保証しないこと、最終承認者、事故時の監査手順
